# PolicyLens Requirements

Product: **PolicyLens** — GMC Policy Intelligence & QMS Extraction

Standalone demonstration project for Group Medical Cover (GMC) policy document intelligence. The Protrac chatbot is reference material only and is not a runtime dependency.

## Assignment mapping

| Assignment requirement | PolicyLens capability |
|------------------------|----------------------|
| Automated insurer & TPA detection | Identity field group + evidence-backed extraction |
| Previous year / tenure / premium | `previous_policy` fields with date/currency normalization |
| Family structure & sum insured tiers | `policy_structure` |
| Demographics & total lives | `demographics` (no invented totals) |
| Room rent, ICU, pre/post hospitalization | `hospitalization` |
| Maternity benefits & limits | `maternity` |
| Waiting periods & PED | `waiting_periods` |
| Other benefits (daycare, OPD, AYUSH, etc.) | `other_benefits` |
| Infertility, surrogacy, ambulance | `infertility_and_ambulance` |
| Corporate buffer & waivers | `buffer_and_waivers` |
| Structured QMS JSON | Versioned Pydantic schema + API/CLI export |
| Adaptability across insurers | Hybrid retrieval + terminology aliases; no rigid templates |
| No hardcoded sample answers | Pipeline-generated outputs only |

## Acceptance criteria

1. Multiple PDF upload, process, reprocess, delete, duplicate detection.
2. Page-level text/table/OCR extraction with parser metadata.
3. Pinecone (primary) and LocalVectorStore (fallback) with identical interfaces.
4. Neo4j (primary) and LocalGraphStore (fallback) with identical interfaces.
5. Hybrid lexical + semantic retrieval with document isolation.
6. Every non-null field has page evidence from the source document.
7. Unsupported values are `null` with status `unknown`.
8. Conflicts set `status=conflict` and do not silently pick a winner.
9. Sample outputs in `outputs/sample/` generated by the pipeline.
10. Tests cover hashing, OCR decision, adapters, normalization, evidence, APIs.
11. Explicit Pinecone/Neo4j mode never silently falls back to local.
12. README discloses paid services, assumptions, and limitations.

## Non-goals

- Protrac ERP authorization / MongoDB / Protrac APIs
- Claiming 100% extraction accuracy
- Inventing policy values from general insurance knowledge
